# SkladBG → Temu

Скрейпър за https://skladbg.net/ и приложения Temu шаблон. Python 3.11+ със стандартната библиотека. Пакетът включва оригиналния шаблон, GitHub Actions workflow и попълнен пример от пълно сканиране.

## Пускане в GitHub

1. Качете съдържанието на папката `skladbg-temu-scraper` в корена на repository. Включете скритата папка `.github`.
2. Отворете **Actions → SkladBG to Temu → Run workflow**.
3. Оставете **limit = 0** за всички разпознати подходящи налични продукти.
4. Свалете **skladbg-temu-results** от **Artifacts**.

Нормалното изпълнение винаги сканира сайта отново. API ключ не е необходим за продуктовите данни.

## Избор и проверка на продуктите

Скрейпърът обхожда всички страници на публичния WooCommerce API. Полученият брой и уникалните ID трябва да съвпадат с брояча на сайта. Липсваща страница или повторени ID спират изпълнението.

Включват се само налични, продаваеми продукти без backorder. Категориите се четат от **Category Name** на приложения шаблон. Правилата използват конкретния вид продукт. Например играчка нож не се включва като истински нож, шапка за плуване като туристическа шапка, нито съдържанието на кутия като самата кутия. Истинските изкуствени елхи са отделени от елховидните сувенири.

`skipped.csv` съдържа всяка изключена обява и причината. Неразпознатите видове изискват преглед или конкретен override. Пълното сканиране на сайта не означава, че всеки наличен продукт има подходяща категория в този шаблон. При реални продуктови вариации всяка налична вариация се обработва отделно. Заглавие „различни цветове“ не създава допълнителни SKU.

## Задължителни полета

Всички задължителни и активни условни полета се проверяват преди записване. Само **Manufacturer** и **EU Responsible person** могат да останат празни, според вашата инструкция. При ново неподдържано задължително поле или невалидна dropdown стойност програмата записва диагностичен отчет и приключва с грешка, без да създаде непълен Excel файл.

За някои текстилни условни полета шаблонът съдържа само ID на родителски материал без списък с условия. Приложимите данни за плътност и нишки се попълват по избрания състав.

Проверяват се и допустимите колони, точните dropdown стойности за категорията, вариантните оси, зависимите Size Family/Sub-Size Family и общият сбор 100% при съставите. Повторените колони за един материал са алтернативи: не се попълва всеки материал със 100%.

Потвърдените по продукт данни имат предимство пред оценките. Настройките по подразбиране отразяват вашите отговори:

- `country_of_origin = "Mainland China"` — Китай, със стойността от dropdown на шаблона.
- `province_of_origin = "Not provided by supplier"` — избраният от вас текст при неизвестна провинция. Това е обозначение на липсваща информация, а не установена провинция.
- `estimate_missing_attributes = true` — липсващите обикновени характеристики се оценяват по продукт и категория. Материал, състав, размер, плътност, възраст, затваряне и други оценки се записват отделно по поле.
- `estimate_missing_packages = true` — размери и тегло за доставка се оценяват по вид продукт. Текстилите се считат за сгънати, топките за изпуснати, а дългите дръжки за разглобени. Продуктовите размери и размерите на опаковката се пазят отделно.
- `listing_quantity = 1` — зададено количество за листинга. Това не е складовият остатък: сайтът публично показва наличност, но не достоверна точна бройка.
- `manufacturer` и `eu_responsible_person` са празни. `shipping_template = "Lazur"` е единствената транспортна стойност в този шаблон.

`estimated_fields.csv` показва за всяка оценка продукт, Excel ред, номер на колона, поле, записана стойност и основание. Маркерът за неизвестна провинция е с `status = supplier_information_missing`. Проверете тези стойности срещу данните на доставчика преди публикуване. Успешната проверка на полетата не означава, че Temu е приел файла. В `summary.json` има `mandatory_fields_complete = true`, но `upload_ready = false`, докато оценките и двете оставени празни идентичности не са потвърдени за публикуване.

## Описания и снимки

В `reviewed_descriptions.json` има описания по 15 действително прегледани снимки. Използват се само при съвпадащи заглавие и изображения. За останалите продукти стандартният режим подготвя описания и bullet points от заглавието и данните на сайта. Източникът на всяко описание е в `descriptions.csv`.

За автоматични описания по снимките добавете **OPENAI_API_KEY** в **Settings → Secrets and variables → Actions** и включете **vision** при Run workflow. `vision_limit = 20` ограничава анализа до 20 заявки, а **0** обработва всички останали подходящи продукти. Ключът се подава през secret и не се записва в repository. API заявките се таксуват по вашия OpenAI акаунт. При липсващ ключ визуалният режим спира с ясна грешка. При неуспешна отделна заявка се запазва описанието от изходните данни и се записва причината.

Моделът анализира първите две изображения. Описва видимите форма, цвят, шарка и конструкция. Не добавя измислени сертификати, безопасност, температурни характеристики или невидими факти. Оценените структурирани атрибути са в отделния отчет и не се представят като потвърдени факти в описанието. Кешът се използва само при непроменени продукт, снимки, модел и инструкции.

## Настройки по продукт

В `product_overrides.json` ключът е ID от отчета. Пример за структурата:

```json
{
  "4977": {
    "category_id": 9995,
    "package_weight_g": 350,
    "package_cm": [24, 24, 12],
    "quantity": 10,
    "individually_packed": "Yes",
    "fields": {"121 - Material": "Stainless Steel"}
  }
}
```

Override може да съдържа само полета, без да променя категорията. Допълнителни ключове: `country_of_origin`, `province_of_origin`, `set_quantity`, `size`, `age_group`, `shape`, `materials`, `product_identification`. `fields` приема точно име или цифров номер на колона. За повторено име използвайте номера, ако искате конкретната колона. Избраната категория винаги трябва да съществува в шаблона.

**Base Price - EUR** е текущата цена, **List Price - EUR** е редовната цена, не по-ниска от текущата. Неподдържана валута спира обработката. „12 броя в стек“ се пази като информация за търговската опаковка и не е доказателство за продаван комплект. Броят на комплектите се извлича само от изрични формулировки за комплект.

## Резултати

- `TEMU_SKLADBG_001.xlsx` — попълнен оригинален шаблон. Над 4 996 реда резултатът се разделя на части.
- `estimated_fields.csv` — всички оценки и непредоставени данни по поле.
- `review_required.csv` и `product_audit.json` — подробна проверка по продукт и Excel ред.
- `product_types.csv` — брой налични обяви по продуктов тип/категория, а не налични физически бройки.
- `skipped.csv` — изключени продукти и причини.
- `descriptions.csv` — описания и източник.
- `summary.json` — контролни бройки и резултат от проверките.
- `template_schema.json` — категориите и настройките на оригиналния шаблон.

Служебните редове 1–4, останалите листове, dropdown метаданните, стиловете, проверките и формулата за име на категория са запазени. Променят се само продуктовите редове на **Template**. Не се добавят отчетни колони в Temu файла.

## Локално изпълнение

```bash
python -m unittest discover -s tests -v
python scraper.py
python scraper.py --vision --vision-limit 0
python scraper.py --limit 15
python scraper.py --catalog output/catalog_snapshot.json
```

Пазете `output/`, `.env` и ключовете извън repository. Извлеченият суров каталог е локален checkpoint и не се включва в GitHub artifact.

Бройките и проверките на конкретния доставен резултат са в `verification.json` и `example_results/summary.json`. Снимките за автоматичния визуален режим са тествани с mock API, без платени заявки в тази проверка.

Документация: [WooCommerce Products API](https://developer.woocommerce.com/docs/apis/store-api/resources-endpoints/products/), [OpenAI image inputs](https://developers.openai.com/api/docs/guides/images-vision).
